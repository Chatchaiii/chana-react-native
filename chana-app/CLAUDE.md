# Chana — project notes for Claude

Read this before working on the app. Keep it up to date when architecture, conventions or preferences change.

## Stack

- Expo SDK 57, expo-router 57, React Native 0.86 (New Architecture), React 19, React Compiler on, typed routes on.
- Animations: react-native-reanimated 4 + react-native-worklets. Gestures: react-native-gesture-handler.
- Icons: the user's own icons in `assets/icons` (24px SVGs, SF Symbols-style names like `chevron.right`, `home.fill`), converted by `npm run icons` into `src/constants/icons.generated.ts` and rendered via `ThemedIcon icon="name"` at 18px (`Icon` with a raw color, e.g. on photos). No icon library — Hugeicons was removed; don't add one back. Native toolbar buttons can't draw SVGs: icons listed in `TOOLBAR_ICONS` (scripts/generate-icons.mjs) are also rendered to black PNGs in `assets/icons/toolbar` (@1x/2x/3x, via the `@resvg/resvg-js` dev dependency) and exported as `ToolbarIcons` from `src/constants/toolbar-icons.generated.ts`; use them with `iconRenderingMode="template"` so the system tints them (black/white in light/dark). SF Symbols / Material symbols only where there's no own icon yet (the create button's `square.and.pencil`). `star`/`star.fill` and `info.circle` are placeholders drawn by Claude until the user designs their own.
- Other: expo-image, expo-haptics, expo-status-bar. No font packages (custom fonts were tried and reverted — keep the system font).
- The user runs the app in **Expo Go** on an iPhone; the dev server (Metro on :8081) is usually already running.

Tabs: `(home)` (Home/posts), `places`, `wishes` (Reminders-style list, see `WishItem`; filtered by status tiles All (open wishes) / Completed (a wish checked or unchecked lingers `TOGGLE_LINGER` = 5s, measured from its `toggledAt`, before it leaves its list) and person chips Everyone / each author, each row's counts take the other row's filter into account), `calendar` (see Calendar below), plus `activity`, `saved`, `couple` (placeholder pages, no create/search).

- **Orientation**: the app rotates (`app.json` `orientation: "default"`). Landscape: `ScreenScrollView` and `SheetContent` keep content clear of the notch (side safe-area insets), the menu scrolls when it doesn't fit, sheets scroll when taller than the screen.
- **Auth**: one flow for sign-in and sign-up, passwordless by default. Email → code (`verify`) → existing account: signed in; new email: `create-account` asks for a name. `verify` offers "Use password instead" (`password`, back = "Use a code instead"); resend has a 30 s cooldown; codes auto-submit on the 6th digit and clear on a wrong one. ProfileSheet's Log out calls `signOut()`.
- **Tabs + drawer** (`app/(app)/_layout.tsx`): the tabs are a headless tab navigator (`Tabs`, `TabSlot`, a hidden `TabList` of `TabTrigger`s that only declares the routes; from `expo-router/ui`), so each tab keeps its stack while another is shown. Use the `Tabs` *component*, not the `useTabsWithTriggers` hook: with React Compiler on, the hook's `NavigationContent` element gets cached and the tab state the menu sees goes stale. `AppDrawer` wraps the `TabSlot` in the `SideDrawer` and only enables the open-swipe while the current tab is on its `index` (`getFocusedRouteNameFromRoute`), so on pushed pages a swipe right is the native back gesture.
- **SideDrawer** (`components/layout/side-drawer.tsx`): the app's own drawer, Claude / Threads style (the stock drawer navigator is not used: it couldn't swipe from anywhere, and didn't cancel presses). The menu lies under the screens (80% wide, max 360); the screen slides aside, rounded, edged and washed out, the menu slides in with a slight parallax. One shared value `progress` (0 closed, 1 open) drives everything on the UI thread. A Pan gesture over the whole screen moves it: it only activates on a sideways swipe towards where the drawer can go (5pt, less than a ScrollView needs, so lists keep vertical scrolling), follows the finger, and settles with `DrawerSpring` (`constants/motion.ts`) at the finger's speed; a flick is projected 0.2s ahead to decide open or closed. **Nothing may re-render while it moves** (rendering at the start of the slide, above all the screens' native headers, made it skip its first frames: measured as a 134pt jump): `useDrawer()` returns a value that never changes (`open()`, `close()`); the one React state `restsOpen` (swipe direction, accessibility) is set in the spring's finished callback; the tap-to-close overlay over the screen is always mounted and switched with `useAnimatedProps` (`pointerEvents` from the shared value `headingOpen`). Plays `HapticStyles.drawer` at either end; Android back closes it. Sideways scrollers go in a `DrawerSwipeBlocker` (the image carousel: `enabled` from its second image on, so on the first image a swipe right opens the menu).
- **Presses during a swipe** (`utils/press-guard.ts`): RN doesn't cancel a press when the drawer's swipe takes over. While a finger drags the drawer (and 150ms after, as the press arrives a moment later) `isPressBlocked()` is true: `ThemedPressable`, `FocusArea` and the drawer's own overlay ignore the press, and a `ThemedPressable` starts no press feedback. Feedback that began before the drag is cleared through `setActivePress` (the pressable under the finger registers its press animation). Deliberately not a shared value every pressable reads: that re-evaluated every pressable's style when the drawer started moving. Not blocked while the drawer only settles, so a menu item can be tapped right after a flick.
- **TabStack** (`components/layout/tab-stack.tsx`): layout of every tab. A `Stack` (pushed pages get a minimal back button: chevron only) declaring `index` first, then `new` as a modal and `profile` as a sheet (`SheetScreenOptions`, also exported for tab-specific sheets) (declared screens are ordered before file routes, so without `index` first a tab would open on `new`). Also exports `unstable_settings` (`initialRouteName: "index"`), which each tab layout re-exports.
- **TabScreen** (`components/layout/tab-screen.tsx`): takes `tab` (and optional `title`, defaults to `tab.title`). Sets header (native menu button via `Stack.Toolbar placement="left"` with the user's `line.3.horizontal` from `ToolbarIcons`; avatar right in a `HeaderButton`, transparent), `Stack.SearchBar`, and bottom `Stack.Toolbar` (search slot + create button → `tab.create.href`). Search is global; `SearchResults` groups by `tab.searchTitle`. Toolbar must be declared in pages, not layouts; iOS 26+ only.
- **AppMenu** (`components/layout/app-menu.tsx`): the menu as its own screen. A "CHANA" header that stays put (a hairline appears under it once content scrolls beneath) and a ScrollView with one group of `Button`s per `MenuSections` entry (`variant` row/list → `sectionStyles` + `buttonProps` lookup tables, optional `spaceBefore`) and the `Logo`. A `MenuItem` switches tabs with `useTabTrigger().switchTab` (active = `prominent`; tapping the active one just closes) and closes the drawer.
- Adding a tab: entry in `Tabs` (incl. `href`, `profileHref`) and in `MenuSections` + folder with the one-line `_layout.tsx`, an `index.tsx` using `TabScreen`, a `new.tsx` using `CreateScreen` (only with `create`), and the one-line `profile.tsx`. Tabs without `create` use `<TabStack withCreate={false} />` in their layout (declaring a missing `new` route warns).
- **Calendar** (`calendar/index.tsx`): a `Calendar` in a card, with a dot (`markedDates`) on every day that has something of the kinds switched on; below it, everything dated on the picked day, gathered from three sources: the calendar's own events (`useEvents()`), posts by `postedAt` and visited places by `visitedOn` (`useVisitedPlaces()`), compared with `isSameDay`. Three `FilterButton` chips (Events / Posts / Places, each with that day's count) switch each kind's list on and off (multi-select, all on to begin with); each visible kind with items is its own section (heading + `List` card). Events have a "…" button that offers to delete (native alert); a post row opens `/post/[id]`, which is in the Home tab, so Back from it lands on the Home feed; places use `PlaceItem`. `calendar/new.tsx` is the form to add an event (`CreateScreen` with children: title `TextField`, `Calendar`, "Add event"); the calendar screen passes the picked day to it by overriding the tab's `create.href` with a `date` param.
- Places has `places/[id]` (place detail page, opened from `PlaceItem`) and the sheet `places/[id]/visited-date` (declared in the places layout): inline `Calendar` + "Save date"; the date only applies on Save, swiping the sheet away discards it. Unmarking a visit asks for confirmation (`Alert.alert`, destructive Remove). The page's local state (ratings) lives in `PlaceContent`, keyed by place id; visits come from the `place-visits` store.
- Routes only one tab has are declared as `children` of `TabStack` in that tab's layout. Home has `post/[id]` (the post detail page, opened by tapping a post in the feed; a `CommentComposer` sits below its ScrollView in a plain flex column, sending scrolls the new comment into view) and declares `post/[id]/options`: a native `formSheet` (`sheetAllowedDetents: "fitToContents"`, grabber) opened from a post's "…" button with the post id. Sheet bodies use `SheetContent` (no bottom safe-area padding: on iOS 26 the sheet floats).

## Conventions

- Files kebab-case; always import via `@/…` (no relative imports); double quotes; Prettier formatting. Imports sorted: `@/…` first (alphabetical by path), then packages.
- Naming: the `Themed` prefix is only for thin wrappers of RN primitives that add a theme color or the app's feel (`ThemedText`, `ThemedTextInput`, `ThemedView`, `ThemedPressable`); everything else is named for what it is (`Button`, `Icon`, `Avatar`, …). Suffixes: `…Item` = a row in a list (`ListItem`, `PostItem`, `PlaceItem`, `WishItem`, `ActionItem`, `CheckItem`, `InfoItem`); `…Field` = something you type into (`TextField`, `SubmitField`, `CodeField`); `…Screen` = the frame of a whole screen (`TabScreen`, `AuthScreen`, `CreateScreen`); `…Sheet` = the body of a sheet. Domain types live in `src/types`, stand-in content in `src/data`, never in components or `constants/`.
- **Components are grouped by folder** (`src/components/<folder>/<name>.tsx`, imported as `@/components/<folder>/<name>`): `ui/` = building blocks that know nothing about the app's data (text, buttons, icons, lists, fields, images); `layout/` = the frames screens sit in (drawer, menu, tab screen and stack, scroll view, sheet); `auth/`, `posts/`, `places/`, `wishes/`, `profile/` = components for one feature, built from `ui/`. A feature component that a second feature needs moves to `ui/`. One component per file, except a small piece that only exists for its neighbour (`CheckCircle` in `check-item.tsx`, `Logo` in `wordmark.tsx`, `HeaderButton` in `tab-screen.tsx`). No index files: import each component from its own file.
- **No scroll-to-top on header taps.** `ScreenScrollView` sets `scrollsToTop={false}`: iOS scrolls a page to the top on a tap in the status bar or anywhere in the header, which fired by accident next to the header buttons. Keep it off on any screen-level scroll view.
- **No scrollbars.** Every scroll view hides its indicators: `ScreenScrollView` and `SheetContent` do it for screens and sheets; a ScrollView / FlatList used directly sets `showsVerticalScrollIndicator={false}` / `showsHorizontalScrollIndicator={false}` itself.
- **No magic numbers for shared design values.** Use `Spacing`, `Radius`, `ContainerSizes`, `Colors` via `useTheme()`, `OverlayColors` for UI on top of photos, `Timings` / `PressIn` / `PressOut` for motion, `HapticStyles` + `playHaptic` for haptics. Component-specific constants (e.g. `DOT_SIZE`) stay local, in SCREAMING_CASE at the top of the file.
- Styles: `StyleSheet.create` at the bottom of the module, camelCase keys; variants as lookup tables (`TypeColors`, `sizeStyles`) composed in a style array; theme colors applied inline. Spacing around a component is set by its parent (via `style`), not baked into the component.
- Props: component props types are `<Component>Props`, extend the underlying RN props when they forward them, and use defaults in the destructuring. Content comes in through props, never hardcoded in a component.
- Reanimated: `.get()` / `.set()` on shared values (React Compiler), `scheduleOnRN` from react-native-worklets to call JS from worklets.
- Prefer eased `withTiming` (`Timings.*`) over springs for transitions — the user found springy, large motion "too much". Springs only for press feedback, the side drawer (`DrawerSpring`: critically damped, so no bounce, but it can take over the finger's speed) and the welcome-screen intro (the user asked for damping there instead of a linear-feeling curve).
- Comments: short, explain *why*; match the surrounding density.

## Gotchas learned

- A ScrollView's `contentOffset` prop is re-applied whenever it changes. Never derive it from a value that changes while scrolling (e.g. a parent that follows the current page) — capture it once with `useState(initial)`. This made `ImageViewer` snap and skip pages.
- `StyleSheet.absoluteFillObject` doesn't exist in RN 0.86 — spell out `position/top/right/bottom/left`.
- The root view is painted in the menu color (`app/_layout.tsx`), so the screen's rounded corners blend into the menu while it slides.
- A `Modal` that never finishes its close animation stays on top invisibly and blocks all touches. Always call `onClose` when the close animation ends (don't gate on `finished`), guard against double dismiss.
- Haptics: anything that both taps a ThemedPressable and opens/closes the drawer plays two haptics.
- Never render optional strings with `&&` (`{text && <ThemedText>…}`): an empty string or `0` lands outside `<Text>` and crashes. Use a ternary or an explicit check (`count > 0`).
- `experimental_backgroundImage: "linear-gradient(...)"` works natively (no expo-linear-gradient needed).
- Adding/changing an icon: drop the SVG into `assets/icons` and run `npm run icons` (to use it in a native toolbar button, also add its name to `TOOLBAR_ICONS`). Draw shapes in black and cut-out details in white (the generator turns white into a transparent mask cut-out, so `.fill` icons work in dark mode); a white 24×24 background rect and clip-path wrappers are stripped. Figma "inside"/"outside" strokes export as `<mask>` shapes, which `Icon` can't draw: the generator skips masked shapes with a warning (fine for `bell`, whose fill already covers it), so prefer centre strokes or Outline stroke. Never edit `icons.generated.ts` by hand.
- `@expo/ui` date pickers (SwiftUI compact popover, inline calendar) ignore `tint` / `accentColor` in Expo Go and stay system blue; tried modifier order, a custom Popover, updating `@expo/ui` and a plain-string tint. The app no longer uses them: `Calendar` is drawn by the app (`@expo/ui` is still installed but unused).
- Should the native inline `DateTimePicker` come back: it sits in a `Host` that measures its height only when it renders. In a sheet the width settles after mount, so it opened too tall until a date was picked; measuring the container with `onLayout` and passing `style={{ width }}` fixed it.
- Custom header items (`headerLeft`/`headerRight`) only receive taps on the React view itself; the rest of iOS 26's glass circle belongs to the header, where a tap scrolls the page to the top. A bare 18pt icon left most of the circle dead, so the menu needed several taps. Wrap them in `HeaderButton` (36pt; 44pt makes the glass grow into a pill). On iOS 27 even that isn't enough: every tap on a custom header item also scrolls to the top. Native `Stack.Toolbar.Button`s don't, so the menu button is native; the avatar stays custom by the user's choice (it may still scroll on iOS 27).
- Claude's brand fonts (Styrene, Tiempos) are licensed — don't add them.
- Never call `SplashScreen.preventAutoHideAsync()` without a matching `hideAsync()` — on Android the splash then never disappears (iOS hides it anyway, so it looks fine there).
- `Stack.Toolbar.Button` on Android needs an image source, not an SF Symbol, and warns even when `hidden`. `TabScreen` renders the create button only once `useMaterialSymbolSource("edit_square")` has produced the Android image.
